# DSH 网络助手

DeepSeek Harness 本地插件：分别管理模型连接、开发终端和本机代理规则。安装后默认“跟随宿主”，不自动切换网络，也不覆盖已有渠道地址或清空已有模型。

## 安装与使用

已验证宿主：DeepSeek Harness **0.2.2-rc.1 macOS 桌面版**。声明兼容 0.2.1-rc.5，但尚未在该版本及 Windows 真机验收。

1. 打开 Harness → 插件 → 添加方式 → 安装第三方插件。
2. 选择本地项目目录，或填写打包生成的 `.tgz` 文件绝对路径。
3. 启用插件，打开侧栏“网络助手”。
4. 先在“代理设置”选择来源并保存，再选择顶部默认模式。可以为单个 API 目标覆盖默认策略。

Windows 建议复制 `.tgz` 安装包到本机后安装。构建产物已包含 undici 与 js-yaml，无需在 Windows 安装开发依赖；Harness 提供宿主 SDK 与 React。安装仍由 Harness 自己的插件管理器处理依赖和版本校验。

| 模式 | 行为 |
| --- | --- |
| 跟随宿主 | 沿用原 dispatcher；全新安装不接管全局网络 |
| 直连 | 受管目标直接建立连接 |
| 智能 | 模型先尝试直连，建连失败后尝试代理；终端优先使用已连通的代理端口 |
| 仅代理 | 受管目标必须经过指定 HTTP(S) 代理，失败时不回退直连 |

智能切换只发生在 TCP/TLS 建连阶段。已经发送的聊天请求不会自动重放，HTTP 401/403/429/5xx 也不会触发切换。代理端口可连接仅说明监听正常，不等于目标网站或模型可用。

## 模型接入

- 读取宿主公开的可配置渠道目录；未配置的空供应商模板不展示。
- 已有渠道只管理路由。新增接入使用真实 API 地址，发布为 `net-assist-*` pi-ai 渠道。
- 可手工填写模型 ID，也可显式获取模型目录。目录报错或返回空列表时保留已有模型；只有主动编辑并清空列表才撤下该受管渠道的模型。
- “连接诊断”只验证 HTTP 连接；“测试真实对话”通过宿主 LLM 服务发起最多 24 个输出 token 的真实调用，可能计费。
- 密钥留空不强制创建凭据引用。部分 OpenAI 兼容 SDK 自身要求非空认证，本机免密服务可按其说明填写占位值。
- 目标按 origin 匹配，同一协议、域名、端口共用路由；路径不同不会自动区分。未公开基础地址的官方宿主渠道仍沿用宿主网络，界面明确提示。

密钥保存在宿主凭据服务，前端只接收“是否已配置”。更换 origin 后不会沿用旧密钥。请求记录只保留有限条目，包含 origin、方法、状态、耗时及错误码，不记录对话正文、查询参数或密钥。

## 终端代理

开启“终端代理”，并选择直连、智能或仅代理，然后新建 CMD、PowerShell（Windows）或 Terminal（macOS），也可以生成会话脚本自行运行。

新终端继承插件的回环 HTTP/CONNECT 网关地址、代理环境变量和 Git 会话级 `http.proxy` 配置，不改写 Git 全局/仓库配置和系统环境。网关使用随机端口及随机认证，仅监听本机，不解密 HTTPS。

- 适用于 Git HTTPS、curl 等读取代理环境的客户端。
- Git 检测使用 `git ls-remote https://github.com/octocat/Hello-World.git HEAD`，不克隆或推送。
- CMD 是命令解释器，是否走代理取决于其中运行的程序；不同版本的 PowerShell、npm、Node 可能需要自己的代理参数。
- 已打开的终端环境不会被回写。切换到跟随宿主、暂停、停用或重载插件后，应关闭受管终端并重新打开。
- **Harness 自动执行的命令、Git SSH、WSL、容器及远程终端尚未接管。** 当前核验的宿主没有可直接用于所有命令的公开代理环境注入契约，界面显示“待宿主适配”。

会话脚本包含仅用于本机网关的临时认证信息，使用私有文件权限创建，插件停用时清理。不要分享这些脚本。

## 一键配置本机代理规则

支持 Clash Verge Rev 的当前运行 YAML + 全局扩展 `Script.js`，以及独立 mihomo 配置 YAML。其他客户端提供规则片段，暂不承诺自动写入。

1. 在“规则助手”发现候选文件，确认实际运行配置和已启用的全局脚本；设置本机控制接口。控制密钥可从选定运行 YAML 读取，或使用宿主凭据存储。
2. 连接控制接口，选择当前确实落到代理节点的策略组。DIRECT、REJECT 和循环选择不会被接受。
3. 选择模型、GitHub、npm 域名范围，生成预览。模型范围只包含当前路由为智能或仅代理的可配置目标。
4. 确认后写入精确 DOMAIN 规则，保存恢复快照，重载内核并核验规则。失败时回滚。
5. “撤销托管规则”还原原始文件并重载。若外部程序改过文件，则停止覆盖，避免破坏新配置。

Verge 的订阅更新持久性依赖所选全局脚本已启用。控制 API 规则核验成功只表示当前规则已装载；“查看活跃连接命中”用于确认实际连接。插件不会将“配置成功”冒充“真实请求已经经过代理”。

## 订阅内核

提供自己已有的 **mihomo 可执行文件绝对路径**，保存 Clash YAML 订阅后可启动、停止和选择节点。只启动本插件拥有的子进程，使用私有运行目录及回环随机端口，不开启 TUN、不写系统代理。

首版没有实现自动下载内核、测速及其他订阅格式转换。订阅默认要求 HTTPS；HTTP 仅允许本机测试地址。订阅及控制认证信息不投影到前端状态。

## 开发与构建

Node.js >= 22.14：

```sh
npm ci
npm run check
npm run build
npm pack --pack-destination output
```

`npm run dev` 启动独立调试页面，默认监听 `127.0.0.1:5186`，状态保存在项目 `.dev-state/`，使用与插件相同的 Engine。它用于界面调试，**不能替代真实 Harness 的安装、RPC、渠道发布和对话验证**。

主要模块：`src/host.js` 宿主入口与 owner RPC；`src/engine.js` 配置和渠道协调；`src/network.js` 请求路由；`src/terminal.js` 终端网关；`src/rules.js` 规则快照与回滚；`src/core.js` 子进程；`src/ui.jsx` 实际交互界面。

验收范围与已知限制见工作区 `repowiki/zh/DeepSeek-Harness-网络助手实现与验收.md`。
