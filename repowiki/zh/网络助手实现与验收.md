# 网络助手实现与验收

适用版本：0.1.5。已验证环境：macOS，DeepSeek Harness 0.2.2-rc.1。Windows 与 Harness 0.2.1-rc.5 尚未真机验收。

## 模型网络策略

插件按 HTTPS/HTTP origin 管理可配置的模型目标，单个目标策略优先于默认策略。官方账号渠道未公开可配置基础地址时，沿用宿主网络。凭据保存在宿主凭据服务，RPC 状态只投影是否已配置。

- 自动跟随：来源有地址时使用代理，否则沿用宿主 dispatcher；显式启用兼容直连的受管目标可使用兼容连接器。
- 直连：直接连接目标。
- 智能：直接连接优先，TCP/TLS 建连失败后才使用已配置的代理。未选择兼容直连且没有代理地址时，不另行改变模型传输栈。
- 仅代理：必须使用指定 HTTP(S) 代理；没有地址时明确提示。

HTTP 错误、证书错误和已发送的应用请求不会为换路自动重放。模型目录读取失败或返回空列表时保留已有模型。连接诊断、目录获取与真实模型对话分别记录；测试达到 24 token 输出上限单独标记。

## 兼容直连

默认关闭，按已配置的 HTTPS origin 显式启用。先尝试标准 TLS；仅当标准连接发生 ECONNRESET 且尚未发送 HTTP 数据时，尝试省略 SNI 的握手。继续强制验证证书信任链和原 API 域名，保持 HTTP Host、URL、凭据及模型 ID。

服务的默认 TLS 站点必须提供覆盖原 API 域名的有效证书，否则兼容握手拒绝连接。证书错误不会触发兼容尝试；兼容证书验证失败也不会通过切换路径绕过。此功能不是任意网站的通用联网修复。

兼容开关不改写系统 DNS、hosts、TUN 或系统代理，也不固定生产 IP。终端原始 TCP 隧道不解密 TLS；代理出口使用标准 TLS。最近建连方式按 origin 投影，最多保存 500 条内存状态；请求记录不保存正文、查询参数或密钥。

相关实现：`src/network.js`、`src/config.js`、`src/engine.js`、`src/host.js`、`src/ui.jsx`。

## 验证结果

本次已执行构建、15 个 JavaScript 文件语法检查和 Git 差异空白检查。

使用临时可信本机证书、真实 TLS / HTTP 流式服务及 CONNECT 代理进行定向验证：

- 正常直连保持标准 SNI；标准握手重置后可在原目标使用兼容握手。
- 证书域名不匹配、证书不受信任时拒绝；正常握手证书错误不尝试兼容。
- POST 被服务端接收后断开时，不为切换连接方式重放。
- 两种直连握手都失败后，智能模式才尝试指定代理。
- 关闭兼容选项后保留原行为；旧配置默认关闭；未接管目标与原始终端继承策略保持原行为。
- 单个渠道策略覆盖默认策略；暂停、绕过和回环目标行为符合预期；仅代理却没有地址时，插件对话测试在调用模型之前停止。

macOS 真实 Harness 验收：连续 35.19 秒、95 次只读采样确认 Clash 主程序和 mihomo 内核均退出、HTTP 代理端口未监听、系统 HTTP/HTTPS/SOCKS/PAC 均关闭。窗口内同一 GLM 的原生对话收到 OK，插件记录为直连 HTTP 200。没有切换备用模型或改变 API 地址、凭据。随后重复发送也成功；重复请求不在前述完整采样窗口内，网络状态由使用者确认。

临时探针、转发服务、测试证书与私钥已清理，没有纳入源码或安装包。对照其他客户端时需核实实际调用模型，自动备用模型回复不能证明首选 API 直连成功。

## 其他能力与边界

- 终端代理作用于插件新建的本机终端，通过回环认证网关、会话环境和 Git 会话级配置提供 HTTP/CONNECT；已有窗口需重开。
- 宿主自动执行命令、Git SSH、WSL、容器和远程终端尚未接管。
- 规则助手提供预览、快照、应用和回滚，支持 Clash Verge Rev 扩展脚本与独立 mihomo；需要实际可用的本机控制接口及代理策略组。
- 订阅内核只运行用户提供的 mihomo 可执行文件，不自动下载、不启用 TUN、不修改系统代理。
- PAC、SOCKS 上游和自动内核下载尚未实现。端口连通、控制接口规则装载与真实模型成功是不同的验收项。
